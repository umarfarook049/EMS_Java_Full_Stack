How it behaves now
Admin logs in (admin / Admin@123, or code 100001) and lands on the dashboard list. They can add, view, edit and delete employees, and use the green icon to save a month’s salary.
Add Employee is one long form with Personal, Professional (with employment history), Project (optional), Finance, and the initial login password. Saving creates the employee and their login together.
Edit: Employment Code, Gender, Date of Birth, Company Email, and Date of Joining are disabled once filled, and the backend ignores changes to them too.
Employee logs in with their company email or 6-digit code and lands on their own details page. Everything is read-only, and the Finance section lists their last 6 months of payslips with PDF download.
Errors: every field shows its message inline. Backend errors, such as a duplicate code or email, appear on the same fields.
Things to know
The seeded admin record is incomplete. Fill in its details through Edit when you want it complete. The locked fields can be set once if they were never filled.
Existing test employees from earlier versions have no code or new details. Either edit them or delete and recreate them. Their logins still work, by email.
CTC breakup: I store the annual CTC and three components but don’t force them to add up. If you want that rule, say so and I’ll add the check on both sides.
PAN and Aadhar are visible to the admin in the edit form, and in the list API response. If you’d like them masked, I can do that.
Password reset still doesn’t exist. Tell me if you want the admin to be able to reset an employee’s password.
